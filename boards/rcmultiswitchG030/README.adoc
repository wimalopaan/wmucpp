== Deutsch

Der MultiSwitch-E8 schaltet acht Ausgänge über CRSF, beispielsweise für Beleuchtung, Soundmodule oder geeignete Lasttreiber im RC-Modell.
Je nach Hardware und Firmware stehen PWM, Blinkfolgen, Morse, virtuelle Ausgangsgruppen, Lauflicht und Master-/Slave-Betrieb zur Verfügung.
Die Schaltbefehle werden als zusätzliche CRSF-Kommandos übertragen und belegen keinen der normalen RC-Proportionalkanäle.

Dieses Verzeichnis enthält die STM32-Firmware. Der aktuelle gemeinsame Einstiegspunkt ist link:msw30.cc[`msw30.cc`], die Hardwarezuordnung steht in link:devices_3.h[`devices_3.h`].
Ältere Firmwaregenerationen wurden aus diesem Verzeichnis entfernt.
Der tatsächliche Funktionsumfang hängt von den beim Übersetzen aktivierten Optionen ab.

=== Anschluss und Adressen

Ein typischer Aufbau ist:

[source,text]
----
EdgeTX-Sender + ELRS-HF-Modul
             |
          Funkstrecke
             |
       ELRS-Empfänger
             |
       CRSF-Schnittstelle
             |
       MultiSwitch-E8
             |
      acht Lastausgänge
----

Bei einer normalen UART-Verbindung werden Empfänger-TX und MultiSwitch-RX sowie Empfänger-RX und MultiSwitch-TX gekreuzt verbunden; eine gemeinsame Masse ist erforderlich.
Ein Ein-Draht-/Half-Duplex-Aufbau benötigt die passende Hardware und Firmwarekonfiguration.
Die Firmware sucht beim Start nach einer passenden CRSF-Baudrate und, soweit vom Hardwaretreiber unterstützt, nach dem Duplexmodus.

[IMPORTANT]
====
Standard-CRSF ist eine Punkt-zu-Punkt-Verbindung, kein beliebig parallel schaltbarer Bus.
Mehrere aktiv sendende Push-Pull-TX-Ausgänge dürfen nicht zusammengeschaltet werden.
Für mehrere Module vorzugsweise getrennte Empfänger-Schnittstellen oder einen CRSF-Switch/Router verwenden.
Open-Drain, Half-Duplex und Antwortslots sind spezielle Aufbauvarianten und ersetzen keine Prüfung der elektrischen und zeitlichen Busbedingungen.
====

==== Drei verschiedene Adressen

[cols="1,1,3",options="header"]
|===
| Einstellung | Vorgabe | Bedeutung
| `Switch Addr` | `0` | Logische Schaltadresse von 0 bis 255 für die acht realen Ausgänge. Diese Adresse wird im Widget als Tab-/Elementadresse eingetragen.
| `Virtual Addr` | `1` | Zusätzliche logische Adresse für virtuelle Gruppen und Lauflicht, sofern einkompiliert.
| `CRSF Addr` | `200` (`0xc8`) | Geräteadresse für CRSF-Erkennung, Konfigurationsmenü und Telemetrie; im Menü von `192` bis `207` (`0xc0` bis `0xcf`) einstellbar.
|===

Die logische Schaltadresse ist nicht die CRSF-Geräteadresse.
Das Gerät erscheint im Konfigurationsmenü als `MultiSwitch-E@<Switch Addr>:<CRSF Addr>`.
Firmware und Menü zählen reale Ausgänge von `Output 0` bis `Output 7`; MultiSwitch NG zeigt dieselben Ausgänge als `1` bis `8`.

Bei mehreren Modulen logische Schaltadressen und gegebenenfalls virtuelle Adressen so vergeben, dass keine unbeabsichtigte gemeinsame Ansteuerung entsteht.
Für unabhängig erkennbare CRSF-Geräte außerdem eindeutige CRSF-Adressen vergeben.
256 logische Schaltadressen bedeuten nicht, dass 256 Geräte elektrisch an einer UART oder gleichzeitig unter den 16 hier angebotenen CRSF-Geräteadressen betrieben werden können.

ELRS V3 leitet standardmäßig nur die erweiterte Geräteadresse `0xc8` weiter; andere Geräteadressen benötigen die in Electronics beschriebene Routing-Erweiterung.
ELRS V4 unterstützt vollständiges CRSF-Routing. Auch dort bleibt pro normaler serieller Schnittstelle ohne Router nur ein externes Gerät vorgesehen.

==== MultiSwitch NG installieren und einrichten

. Das vollständige Widget-Verzeichnis nach `/WIDGETS/lvglMultiSwNG/` auf die Sender-SD-Karte kopieren, einschließlich der Module, `lang/` und Logos.
. Im Modell das Widget `MultiSw NG` hinzufügen und zur Bedienung ins Vollbild wechseln.
. Unter `Einstellungen` -> `Global` das Protokoll `CRSF` verwenden. Das interne oder externe HF-Modul des Senders muss für CRSF/ELRS eingerichtet sein.
. Unter `Tab Einstellungen` die Standardadresse passend zu `Switch Addr` setzen. Die erste Konfiguration hat Adresse `0` und acht rastende Buttons für Ausgänge `1` bis `8`.
. Elemente benennen und bei Bedarf ihre Art, Ausgangsnummer und physische Zuordnung ändern; mit `Anwenden` übernehmen und speichern.
. Zunächst ohne gefährliche Lasten jeden Ausgang einzeln prüfen; anschließend Lastfunktionen und Verhalten bei Verbindungsunterbrechung prüfen.

Das NG-Widget hat keine funktionalen Widget-Options: Die Konfiguration erfolgt im Vollbild.
Die Oberfläche folgt der EdgeTX-Menüsprache Deutsch oder Englisch.
Ein Element mit Adresse `-1` erbt die Standardadresse seines Tabs; eine explizite Adresse kann auf ein anderes Modul zeigen.
Die Kombination aus Adresse und Ausgang muss über alle Tabs eindeutig sein.

Die unter `Global` eingestellte CRSF-Zieladresse ist wiederum keine logische Schaltadresse.
NG verwendet standardmäßig Ziel `0` (Broadcast); die Zustellung muss zur eingesetzten CRSF-/ELRS-Topologie passen.
Das Wiederholintervall wird in Einheiten von 10 ms angegeben; Vorgabe `100` entspricht einer Sekunde.
Änderungen werden unabhängig davon zeitnah gesendet.

==== Touch, Schalter und proportionale Bedienung

[cols="1,3",options="header"]
|===
| NG-Element | Verhalten mit diesem MultiSwitch
| `Button` | Rastendes Ein/Aus durch Antippen.
| `Schalter` | Ein/Aus-Schaltelement.
| `Taster` | Aktiv während der Betätigung; Touch-Taster werden beim Tab-/Seitenwechsel und Verlassen des Vollbilds zurückgesetzt.
| `3-Positionen` | Mitte sendet `0`, rechts `1`, links `2`. Diese Firmware behandelt beide Nichtnullzustände als Ein; keine Richtungsumschaltung oder zwei unterschiedlichen Lastfunktionen.
| `Schieberegler` | Sendet 0 bis 100 % per `Prop`; am betreffenden Firmwareausgang `PWM Mode = Remote` einstellen.
|===

Eine physische Schalterzuordnung deaktiviert die Touch-Bedienung des zugehörigen Schaltelements.
Bei `3-Positionen` hat der erste zugeordnete Schalter Vorrang, der zweite aktiviert Zustand 2.
Ein Schieberegler kann einer Senderquelle zugeordnet werden: Werte `0` bis `1024` ergeben `0` bis `100 %`, negative Werte ergeben `0 %`.
Für einen Knüppel mit symmetrischem Wertebereich daher eine passende Quelle/Mischung vorbereiten.
Bei zugeordneter Quelle ist der Touch-Schieberegler deaktiviert.

Ein Aktivierungsschalter kann die Bedienung sperren und den Ausgang zurücksetzen.
Exklusivgruppen erlauben nur ein aktives Schaltelement pro Gruppe und gelten tabübergreifend; Schieberegler gehören nicht dazu.
Physische Eingänge werden auch in inaktiven Tabs verarbeitet.
Mehrere NG-Widget-Instanzen desselben Modells teilen Konfiguration, Schaltzustände und Übertragung.

Angewendete Konfigurationen werden standardmäßig automatisch gespeichert, Schaltzustände hingegen nicht.
Nach einem Neustart beginnen Touch-Elemente ausgeschaltet; das ersetzt keine modellseitige Sicherheitsabschaltung.
NG lädt oder migriert die Konfiguration des bisherigen Widgets nicht.

==== Abgrenzung zu anderen Widget-Funktionen

[NOTE]
====
NG bietet auch `S.Port WM` sowie `S.Port ACW 1.5/1.4` an. Die hier beschriebene STM32-Firmware verwendet jedoch CRSF als Eingang.
S.Port, SBus, IBus und SumDV3 aus der übergreifenden Electronics-Dokumentation betreffen andere MultiSwitch-Firmwarevarianten bzw. Transportwege; sie sind nicht automatisch Eingänge dieses Projekts.

Die optionale NG-LED-Farbübertragung (`SetRGB`) macht aus den acht Schaltausgängen keine adressierbaren RGB-LED-Ausgänge: Der Decoder dieser Firmware verarbeitet `SetRGB` nicht.
NG enthält derzeit außerdem keine SHM-Anbindung, Telemetrieaktionen oder das Setzen virtueller Sender-Eingänge/-Schalter.
Virtuelle _Firmware-Ausgangsgruppen_ sind davon unabhängig.
====

=== Firmware konfigurieren

Das CRSF-Gerätemenü konfiguriert den MultiSwitch, das Widget-Menü die Senderbedienung.
Beides sind getrennte Einstellungen: Ein im Widget benannter Button konfiguriert beispielsweise nicht automatisch den PWM-Modus im Gerät.
Dauerhafte Parameteränderungen werden von der Firmware im Flash gespeichert; `Test` und `Operate` sind Laufzeitbedienung und keine gespeicherten Einschaltzustände.
Regelmäßig wiederholte Widget-Befehle können Menütests wieder überschreiben.

==== Globale Einstellungen und Ausgangsfunktionen

[cols="1,3",options="header"]
|===
| Menü | Bedeutung
| `Global` -> `Switch Addr`, `Virtual Addr`, `CRSF Addr`
| Adressierung wie oben beschrieben; `Virtual Addr` nur bei aktivierter virtueller Funktion.
| `Global` -> `PWM f G...`
| Gemeinsame PWM-Frequenz einer Hardware-Timergruppe: Wert 1 bis 200 in Schritten von 100 Hz, also 100 Hz bis 20 kHz. Die Menübeschriftung nennt die zugehörigen Ausgänge.
| `Output n` -> `PWM Mode`
| `Off`: ohne PWM; `On`: PWM mit eingestelltem Tastgrad; `Remote`: proportional per CRSF; `Global/Indiv`: individueller Tastgrad mit globaler Skalierung, sofern diese Funktion genutzt wird.
| `Output n` -> `PWM Duty`
| Lokaler Tastgrad von 1 bis 99 %. Für `Remote` kommt der Wert von den `Prop`-Kommandos, einschließlich 0 und 100 %.
| `Output n` -> `Intervall Mode`
| `Off`: stetiges Schalten; `On`: Blinkfolge; `Morse`: gemeinsamer Morse-Text bei einkompilierter Morse-Funktion. Die zusätzlich sichtbare Bezeichnung `Pattern` ist hier kein eigenständig auswählbarer Lauflichtmodus.
| `Output n` -> `Intervall(on/off)`
| Zeitwerte von 1 bis 255 in Einheiten von 50 ms.
| `Output n` -> `Intervall(count)`
| Anzahl der Blitze einer Folge, 1 bis 4.
| `Output n` -> `Test`
| Einzelnen Ausgang probeweise aus-/einschalten.
| `Operate`
| Optionales Menü zum direkten Schalten aller acht Ausgänge.
|===

Bei Small11/Small12 teilen sich `Output 0` bis `3` sowie `Output 4` bis `7` jeweils eine PWM-Frequenz.
Andere Boards haben andere Timergruppen.
`PWM Expo` ist als Parameter vorhanden, wird vom aktuell verwendeten Blinker jedoch nicht umgesetzt.

==== Morse, virtuelle Gruppen und Lauflicht

`Morse` enthält den Text und die Zeiten für Dit, Dah, Zeichen- und Wortpausen in Einheiten von 100 ms.
Auf Small12 stehen mehrere Textfelder zur Verfügung; nichtleere Teiltexte werden zu einem gemeinsamen Text zusammengefügt.
Am gewünschten Ausgang `Intervall Mode = Morse` wählen und den Ausgang einschalten.

Mit `USE_VIRTUALS` lassen sich unter `Virtuals` vier Gruppen (`Virtual 0` bis `3`) mit jeweils bis zu vier realen Ausgängen definieren.
`Enable Virtuals` aktiviert die Gruppennutzung; angesteuert wird die zusätzliche `Virtual Addr`.
Gruppenmitglieder werden dann nicht mehr durch normale Einzel-Schaltbefehle an `Switch Addr` bedient.
Im NG-Widget entsprechen die vier Gruppen den Ausgängen `1` bis `4` an der virtuellen Adresse.

Mit `USE_PWM_GLOBAL_MODULATION` kann der proportionale Kanal `4` (NG-Ausgang `5`) an der virtuellen Adresse die globale Helligkeit steuern.
Dafür `Virtual 4 = Global Dimming` aktivieren und die betreffenden realen Ausgänge auf `PWM Mode = Global/Indiv` setzen.

Mit `USE_PATTERNS` stehen Lauflichtgeneratoren mit kontinuierlicher oder einmaliger Laufrichtung links/rechts bzw. hin und zurück zur Verfügung.
Mitgliederreihenfolge, Ein-/Auszeiten in Einheiten von 10 ms, Folgeadresse und Gruppe werden im Pattern-Menü eingestellt.
Auf Small12 heißen die Einträge `Pattern Virt. 5` bis `8`.
Die Schaltansteuerung der vier Generatoren erfolgt über die verbleibenden vier Bits der virtuellen Adresse, also NG-Ausgänge `5` bis `8`.
Als Lauflichtmitglieder verwendete Ausgänge werden nicht parallel über normale Einzel-Schaltbefehle bedient.

[IMPORTANT]
====
Globale Dimmung und der erste Lauflichtgenerator überlagern sich bei der Bediennummer NG-Ausgang `5` an der virtuellen Adresse: Dimmung verwendet `Prop`, der Generator den Schaltzustand.
NG sendet bei einem Schieberegler zusätzlich einen Einschaltzustand für Werte größer 0.
Für dieses Bedienkonzept daher nicht gleichzeitig den ersten Generator und globale Dimmung verwenden.
====

Die Parameter `Next Address` und `Group` sowie Intermodul-Kommandos ermöglichen modulübergreifende Lauflichtketten.
Dafür muss der CRSF-Übertragungsweg auch Nachrichten zwischen Geräten transportieren; ein bloß parallel angeschlossener UART-Aufbau garantiert das nicht.

==== Master-/Slave-Betrieb

Mit `USE_SLAVE_COMMAND` kann ein Master über `Global` -> `Slave Cmd` Ausgangszustände senden.
Am Slave unter `Global` -> `Master` die logische Adresse des gewünschten Masters einstellen und bei den betreffenden Ausgängen `Slave = On` setzen.
Diese Ausgänge reagieren dann auf Slave-Kommandos statt auf normale Einzel-Schaltbefehle.
Der Transport zwischen den Modulen benötigt ebenfalls eine passende Routing-/Buslösung.

==== Telemetrie, LED und Failsafe

Small11/Small12 liefern Spannungs- und interne MCU-Temperaturdaten mit den einstellbaren IDs `Cells Id` und `Temp Id`.
Die Temperatur ist keine externe Last- oder Umgebungstemperaturmessung.
Die Firmware überträgt außerdem vorhandene digitale Eingänge als Statusbits; ein nach Masse gezogener Eingang setzt sein Bit.
Die Anzeige dieser Statusbits ist eine Funktion geeigneter Senderprogramme, nicht der allgemeinen NG-Betriebsstatusanzeige.

Bei einkompiliertem `USE_RESPONSE_SLOT` stehen `Response Slot` und `Config resp.` zur Verfügung.
Unterschiedliche Slots dienen der zeitlichen Trennung von Antworten in geeigneten gemeinsamen Busaufbauten.
`Config resp. = Button` erfordert einen tatsächlich vorhandenen und einkompilierten Taster; ein langer Tastendruck aktiviert die Antworten.
Small12 besitzt in der aktuellen Hardwaredefinition keinen solchen Taster.

[cols="1,3",options="header"]
|===
| Status-LED | Bedeutung der Firmwarezustände
| Mittleres Blinken | Suche nach CRSF-Verbindung/Baudrate.
| Langsam, einmal | Betrieb ohne Telemetrie-/Konfigurationsantworten.
| Langsam, zweimal | Betrieb mit dauerhaft aktivierten Antworten.
| Langsam, dreimal | Dauerhafte Antworten im erkannten Half-Duplex-Betrieb, sofern der Treiber diese Erkennung bereitstellt.
| Dauerlicht | Vorübergehend per Taster aktivierte Antworten.
| Schnelles Blinken | Zustand `NotConnected`.
|===

Mit `USE_FAILSAFE` bietet `Failsafe` die Modi `Hold`, `All-Off` und `Set` mit einem Ein/Aus-Muster für acht Ausgänge.
Die Vorgabe ist `Hold`.

[WARNING]
====
Die angebotenen Failsafe-Parameter sind keine Sicherheitsgarantie: Im aktuellen `gfsm.h` ist die regelmäßige Paketprüfung im Laufbetrieb auskommentiert.
Außerdem laufen die Failsafe-Schaltbefehle durch die normale Ausgangszuordnung, wodurch virtuelle, Pattern- oder Slave-Mitglieder betroffen sein können.
Das Verhalten bei Ausfall von Sender, Funkstrecke und serieller Verbindung deshalb am tatsächlichen Aufbau prüfen und für sicherheitsrelevante Lasten eine unabhängige Abschaltung vorsehen.
====

=== Firmware bauen und übertragen

Das gemeinsame Makefile baut `msw30.elf` und `msw30.bin`.
Erforderlich sind die ARM-GCC-Toolchain mit C++26-Unterstützung und die STM32CubeG0/CMSIS-Dateien gemäß den Include-Pfaden des Makefiles.
Für Clang-Builds werden zusätzlich Clang und LLD benötigt; Standardbibliothek und Laufzeitbibliotheken stammen weiterhin aus der ARM-GCC-Toolchain.
Das gesamte wmucpp-Repository wird benötigt; dieses Board-Verzeichnis allein genügt nicht.

Aus diesem Verzeichnis genau den zur Bestückung passenden Build ausführen:

[cols="1,2",options="header"]
|===
| Hardware | Kommando
| Small10 / STM32G030 | `make HW=HW_MSW10`
| Small11 / STM32G031 | `make HW=HW_MSW11`
| Small12 / STM32G051 | `make HW=HW_MSW12 MCU=G051`
| Small12 / STM32G0B1 | `make HW=HW_MSW12`
| Nucleo / STM32G031 | `make HW=HW_NUCLEO`
| WeAct / STM32G031 | `make HW=HW_WEACT`
| WM / STM32G0B1 | `make HW=HW_WMG0B1`
|===

Ohne Optionen wird `HW=HW_MSW12 TOOLCHAIN=gcc` gebaut.
Mit `TOOLCHAIN=clang` wird Clang mit LLVM-LTO verwendet, beispielsweise `make HW=HW_MSW12 TOOLCHAIN=clang`.
Die MCU wird aus der Hardware abgeleitet; nur Small12 erlaubt zusätzlich `MCU=G051`.
Das Makefile setzt die Hardware- und MCU-Defines und wählt Startup und Linkerskript passend dazu.
Unbekannte Optionen und unzulässige Hardware-/MCU-Kombinationen werden abgelehnt.
Weitere Features werden am Anfang von `msw30.cc` gewählt; Small12 ergänzt dort abhängig vom MCU Standardfunktionen automatisch.
`NO_DEFAULTS_MSW12` verhindert diese automatische Ergänzung.
Ausgabedateien liegen getrennt unter `build/<HW>/<MCU>/<TOOLCHAIN>/`.
Varianten können ohne vorheriges `clean` und parallel gebaut werden; Header-Abhängigkeiten werden automatisch erfasst.
`make clean` mit denselben Auswahloptionen entfernt nur die Dateien dieser Variante.

Übertragung mit ST-Link/SWD, beispielsweise für die zuvor passend gebaute Binärdatei:

[source,console]
----
st-flash --reset --connect-under-reset write build/HW_MSW12/G0B1/gcc/msw30.bin 0x08000000
----

Beim WeAct-Board kann die Nutzung von PA14 für Taster oder Debugausgabe mit SWD kollidieren; die Hinweise in `msw30.cc` beachten und gegebenenfalls NRST beim Programmierstart verwenden.
Vor einem Firmwarewechsel die bisherige Konfiguration dokumentieren und danach Parameter sowie Ausgangsverhalten erneut prüfen.

=== Fehlersuche und Grenzen

[cols="1,3",options="header"]
|===
| Symptom | Prüfen
| Widget bedient den falschen oder keinen Ausgang
| `Switch Addr`, geerbte Tab-Adresse, explizite Elementadresse und Nummerierung 0–7 gegenüber 1–8.
| Schieberegler schaltet nur Ein/Aus
| CRSF als NG-Protokoll, `PWM Mode = Remote`, geeignete Last und richtige Senderquelle.
| Einzelner Ausgang reagiert nicht auf den normalen Schalter
| Zuordnung zu virtueller Gruppe, aktivem Pattern oder Slave; Aktivierungsschalter und Exklusivgruppe im Widget.
| Gerät fehlt unter `Other devices`
| Rückkanal, Konfigurationsantworten, CRSF-Geräteadresse, ELRS-Routing und gegebenenfalls Antwortslots.
| NG meldet `CRSF inaktiv`
| Internes/externes HF-Modul auf CRSF/ELRS einstellen. Im Simulator wird stattdessen eine separat eingerichtete serielle Ausgabe benötigt.
| NG zeigt Übertragungs-/Speicherfehler
| Statusmeldung beachten; die Annahme eines Telegramms durch EdgeTX bestätigt nicht dessen Empfang am MultiSwitch.
|===

== English

The MultiSwitch-E8 controls eight outputs via CRSF, for example for lighting, sound modules or suitable load drivers in an RC model.
Depending on the hardware and firmware, it supports PWM, flashing sequences, Morse, virtual output groups, running lights and master/slave operation.
Switching commands are transmitted as additional CRSF commands and do not occupy any of the normal proportional RC channels.

This directory contains the STM32 firmware. The current common entry point is link:msw30.cc[`msw30.cc`]; hardware mappings are defined in link:devices_3.h[`devices_3.h`].
Older firmware generations have been removed from this directory.
The actual feature set depends on the options enabled at compile time.

=== Connections and addresses

A typical setup is:

[source,text]
----
EdgeTX radio + ELRS RF module
             |
          Radio link
             |
        ELRS receiver
             |
        CRSF interface
             |
        MultiSwitch-E8
             |
       Eight load outputs
----

For a normal UART connection, connect receiver TX to MultiSwitch RX and receiver RX to MultiSwitch TX; a common ground is required.
A single-wire/half-duplex setup requires matching hardware and firmware configuration.
At startup, the firmware searches for a suitable CRSF baud rate and, where supported by the hardware driver, the duplex mode.

[IMPORTANT]
====
Standard CRSF is a point-to-point connection, not a bus that can be freely wired in parallel.
Do not connect multiple actively transmitting push-pull TX outputs together.
For multiple modules, preferably use separate receiver interfaces or a CRSF switch/router.
Open-drain, half-duplex and response slots are special configurations and do not replace checking the electrical and timing requirements of the bus.
====

==== Three different addresses

[cols="1,1,3",options="header"]
|===
| Setting | Default | Meaning
| `Switch Addr` | `0` | Logical switch address from 0 to 255 for the eight physical outputs. Enter this address as the tab/control address in the widget.
| `Virtual Addr` | `1` | Additional logical address for virtual groups and running lights, if compiled in.
| `CRSF Addr` | `200` (`0xc8`) | Device address for CRSF discovery, the configuration menu and telemetry; adjustable from `192` to `207` (`0xc0` to `0xcf`) in the menu.
|===

The logical switch address is not the CRSF device address.
The device appears in the configuration menu as `MultiSwitch-E@<Switch Addr>:<CRSF Addr>`.
Firmware and device menus number physical outputs from `Output 0` to `Output 7`; MultiSwitch NG displays the same outputs as `1` to `8`.

With multiple modules, assign logical switch addresses and, where applicable, virtual addresses to avoid unintended simultaneous control.
Also assign unique CRSF addresses to independently discoverable CRSF devices.
Having 256 logical switch addresses does not mean that 256 devices can be electrically connected to one UART or operated simultaneously using the 16 CRSF device addresses offered here.

By default, ELRS V3 only forwards the extended device address `0xc8`; other device addresses require the routing extension described in Electronics.
ELRS V4 supports full CRSF routing. Even there, a normal serial interface is intended for only one external device unless a router is used.

==== Installing and setting up MultiSwitch NG

. Copy the complete widget directory to `/WIDGETS/lvglMultiSwNG/` on the radio SD card, including the modules, `lang/` and logos.
. Add the `MultiSw NG` widget to the model and enter fullscreen mode to operate it.
. Under `Setup` -> `Global`, use the `CRSF` protocol. The radio's internal or external RF module must be configured for CRSF/ELRS.
. Under `Tab settings`, set the default address to match `Switch Addr`. The initial configuration uses address `0` and eight latching buttons for outputs `1` to `8`.
. Name the controls and adjust their type, output number and physical assignments as required; select `Apply` and save.
. First check each output individually without hazardous loads connected; then check load functions and behavior when the connection is interrupted.

The NG widget has no functional widget options: configuration takes place in fullscreen mode.
The interface follows the EdgeTX menu language, German or English.
A control with address `-1` inherits its tab's default address; an explicit address can refer to another module.
The combination of address and output must be unique across all tabs.

The CRSF destination address configured under `Global` is, again, not a logical switch address.
NG defaults to destination `0` (broadcast); delivery must be compatible with the CRSF/ELRS topology used.
The repeat interval is specified in units of 10 ms; the default `100` means one second.
Changes are transmitted promptly regardless of this repeat interval.

==== Touch, switches and proportional control

[cols="1,3",options="header"]
|===
| NG control | Behavior with this MultiSwitch
| `Button` | Latching on/off control operated by tapping.
| `Toggle` | On/off switch control.
| `Momentary` | Active while pressed; touch momentary controls reset when changing tabs/pages or leaving fullscreen mode.
| `3Pos` | Center sends `0`, right sends `1`, left sends `2`. This firmware treats both nonzero states as on; it does not provide direction reversal or two different load functions.
| `Slider` | Sends 0 to 100 % through `Prop`; set the corresponding firmware output to `PWM Mode = Remote`.
|===

Assigning a physical switch disables touch operation of the corresponding switch control.
For `3Pos`, the first assigned switch takes priority; the second activates state 2.
A slider can be assigned to a radio source: values from `0` to `1024` map to `0` to `100 %`, while negative values map to `0 %`.
For a stick with a symmetrical value range, prepare a suitable source/mix.
Assigning a source disables touch operation of the slider.

An activation switch can lock a control and reset its output.
Exclusive groups allow only one active switch control per group and apply across tabs; sliders are not group members.
Physical inputs are processed even on inactive tabs.
Multiple NG widget instances within the same model share configuration, output states and transmission.

Applied configurations are saved automatically by default, but output states are not.
After a restart, touch controls start switched off; this does not replace a model-side safety shutdown.
NG does not load or migrate the previous widget's configuration.

==== Distinguishing other widget features

[NOTE]
====
NG also offers `S.Port WM` and `S.Port ACW 1.5/1.4`. However, the STM32 firmware described here uses CRSF as its input.
S.Port, SBus, IBus and SumDV3 in the broader Electronics documentation refer to other MultiSwitch firmware variants or transport paths; they are not automatically inputs supported by this project.

Optional NG LED color transmission (`SetRGB`) does not turn the eight switch outputs into addressable RGB LED outputs: this firmware's decoder does not process `SetRGB`.
NG currently also lacks SHM integration, telemetry actions and setting virtual radio inputs/switches.
Virtual _firmware output groups_ are independent of these features.
====

=== Configuring the firmware

The CRSF device menu configures the MultiSwitch, while the widget menu configures radio controls.
These are separate settings: naming a button in the widget does not, for example, automatically configure the device's PWM mode.
The firmware saves persistent parameter changes in flash; `Test` and `Operate` are runtime controls, not saved power-on states.
Repeated widget commands can override menu tests.

==== Global settings and output functions

[cols="1,3",options="header"]
|===
| Menu | Meaning
| `Global` -> `Switch Addr`, `Virtual Addr`, `CRSF Addr`
| Addressing as described above; `Virtual Addr` is available only with the virtual feature enabled.
| `Global` -> `PWM f G...`
| Shared PWM frequency for a hardware timer group: values from 1 to 200 in steps of 100 Hz, meaning 100 Hz to 20 kHz. The menu label identifies the associated outputs.
| `Output n` -> `PWM Mode`
| `Off`: no PWM; `On`: PWM at the configured duty cycle; `Remote`: proportional control through CRSF; `Global/Indiv`: individual duty cycle with global scaling, if that feature is used.
| `Output n` -> `PWM Duty`
| Local duty cycle from 1 to 99 %. In `Remote` mode, the value comes from `Prop` commands, including 0 and 100 %.
| `Output n` -> `Intervall Mode`
| `Off`: steady switching; `On`: flashing sequence; `Morse`: shared Morse text when the Morse feature is compiled in. The additional visible `Pattern` label is not a separately selectable running-light mode here.
| `Output n` -> `Intervall(on/off)`
| Time values from 1 to 255 in units of 50 ms.
| `Output n` -> `Intervall(count)`
| Number of flashes in a sequence, from 1 to 4.
| `Output n` -> `Test`
| Switch an individual output off/on for testing.
| `Operate`
| Optional menu for directly switching all eight outputs.
|===

On Small11/Small12, `Output 0` to `3` share one PWM frequency, and `Output 4` to `7` share another.
Other boards use different timer groups.
`PWM Expo` is present as a parameter but is not implemented by the currently used blinker.

==== Morse, virtual groups and running lights

`Morse` contains the text and timing for dits, dahs, character gaps and word gaps in units of 100 ms.
Small12 provides several text fields; nonempty text fragments are combined into one shared text.
Set the desired output to `Intervall Mode = Morse` and switch it on.

With `USE_VIRTUALS`, four groups (`Virtual 0` to `3`), each containing up to four physical outputs, can be defined under `Virtuals`.
`Enable Virtuals` enables group operation; commands use the additional `Virtual Addr`.
Group members are then no longer controlled by normal individual switching commands sent to `Switch Addr`.
In the NG widget, these four groups correspond to outputs `1` to `4` at the virtual address.

With `USE_PWM_GLOBAL_MODULATION`, proportional channel `4` (NG output `5`) at the virtual address can control global brightness.
Enable `Virtual 4 = Global Dimming` and set the relevant physical outputs to `PWM Mode = Global/Indiv`.

With `USE_PATTERNS`, running-light generators support continuous or single left/right or back-and-forth sequences.
The pattern menu configures member order, on/off times in units of 10 ms, the next address and the group.
On Small12, the entries are named `Pattern Virt. 5` to `8`.
The four generators are switched through the remaining four bits of the virtual address, corresponding to NG outputs `5` to `8`.
Outputs used as running-light members are not simultaneously controlled by normal individual switching commands.

[IMPORTANT]
====
Global dimming and the first running-light generator overlap at NG output `5` of the virtual address: dimming uses `Prop`, while the generator uses the switch state.
For a slider, NG also sends an on state for values greater than 0.
For this control setup, do not use the first generator and global dimming simultaneously.
====

The `Next Address` and `Group` parameters, together with intermodule commands, enable running-light chains across modules.
The CRSF transport path must also carry messages between devices; simply connecting UARTs in parallel does not guarantee this.

==== Master/slave operation

With `USE_SLAVE_COMMAND`, a master can transmit output states using `Global` -> `Slave Cmd`.
On the slave, set `Global` -> `Master` to the desired master's logical address and set the relevant outputs to `Slave = On`.
These outputs then respond to slave commands instead of normal individual switching commands.
Transport between modules also requires a suitable routing/bus solution.

==== Telemetry, LED and failsafe

Small11/Small12 provide voltage and internal MCU temperature data with configurable `Cells Id` and `Temp Id` identifiers.
The temperature is not an external load or ambient temperature measurement.
The firmware also transmits available digital inputs as status bits; pulling an input to ground sets its bit.
Displaying these status bits is a feature of suitable radio software, not of the general NG operating status display.

When `USE_RESPONSE_SLOT` is compiled in, `Response Slot` and `Config resp.` are available.
Different slots separate replies in time in suitable shared-bus setups.
`Config resp. = Button` requires a physical pushbutton that is also enabled in the firmware; a long press activates replies.
Small12 has no such pushbutton in the current hardware definition.

[cols="1,3",options="header"]
|===
| Status LED | Meaning of the firmware states
| Medium-rate flashing | Searching for a CRSF connection/baud rate.
| Slow, once | Operation without telemetry/configuration replies.
| Slow, twice | Operation with permanently enabled replies.
| Slow, three times | Permanently enabled replies in detected half-duplex operation, if the driver provides this detection.
| Steady on | Replies temporarily enabled by pushbutton.
| Fast flashing | `NotConnected` state.
|===

With `USE_FAILSAFE`, `Failsafe` offers `Hold`, `All-Off` and `Set` modes, with an on/off pattern for eight outputs.
The default is `Hold`.

[WARNING]
====
The available failsafe parameters are not a safety guarantee: in the current `gfsm.h`, regular packet checking during operation is commented out.
Furthermore, failsafe switching commands pass through the normal output mapping, which can affect virtual, pattern or slave members.
Therefore, test behavior when the radio, RF link or serial connection fails on the actual setup, and provide an independent shutdown for safety-critical loads.
====

=== Building and flashing the firmware

The shared Makefile builds `msw30.elf` and `msw30.bin`.
The ARM GCC toolchain with C++26 support and STM32CubeG0/CMSIS files are required according to the include paths in the Makefile.
Clang builds additionally require Clang and LLD; standard and runtime libraries still come from the ARM GCC toolchain.
The complete wmucpp repository is needed; this board directory alone is insufficient.

From this directory, run exactly the build matching the installed hardware:

[cols="1,2",options="header"]
|===
| Hardware | Command
| Small10 / STM32G030 | `make HW=HW_MSW10`
| Small11 / STM32G031 | `make HW=HW_MSW11`
| Small12 / STM32G051 | `make HW=HW_MSW12 MCU=G051`
| Small12 / STM32G0B1 | `make HW=HW_MSW12`
| Nucleo / STM32G031 | `make HW=HW_NUCLEO`
| WeAct / STM32G031 | `make HW=HW_WEACT`
| WM / STM32G0B1 | `make HW=HW_WMG0B1`
|===

Without options, the default is `HW=HW_MSW12 TOOLCHAIN=gcc`.
Use `TOOLCHAIN=clang` for Clang with LLVM LTO, for example `make HW=HW_MSW12 TOOLCHAIN=clang`.
The MCU is derived from the hardware; only Small12 additionally supports `MCU=G051`.
The Makefile supplies hardware and MCU defines and selects the matching startup and linker script.
Unknown options and unsupported hardware/MCU combinations are rejected.
Additional features are selected at the start of `msw30.cc`; Small12 automatically adds default features there depending on the MCU.
`NO_DEFAULTS_MSW12` disables these automatic additions.
Outputs are separated under `build/<HW>/<MCU>/<TOOLCHAIN>/`.
Variants can be built incrementally and in parallel without a preceding `clean`; header dependencies are tracked automatically.
`make clean` with the same selection options removes only that variant's files.

Flash using ST-Link/SWD, for example for the binary previously built for the correct hardware:

[source,console]
----
st-flash --reset --connect-under-reset write build/HW_MSW12/G0B1/gcc/msw30.bin 0x08000000
----

On the WeAct board, using PA14 for a pushbutton or debug output can conflict with SWD; follow the notes in `msw30.cc` and use NRST when starting programming if necessary.
Before changing firmware, record the existing configuration and check parameters and output behavior again afterwards.

=== Troubleshooting and limitations

[cols="1,3",options="header"]
|===
| Symptom | Check
| Widget controls the wrong output or no output
| `Switch Addr`, inherited tab address, explicit control address and numbering 0-7 versus 1-8.
| Slider only switches on/off
| CRSF as the NG protocol, `PWM Mode = Remote`, a suitable load and the correct radio source.
| Individual output does not respond to its normal switch
| Assignment to a virtual group, active pattern or slave; activation switch and exclusive group in the widget.
| Device missing under `Other devices`
| Return path, configuration replies, CRSF device address, ELRS routing and response slots where applicable.
| NG reports `CRSF inactive`
| Configure the internal/external RF module for CRSF/ELRS. The simulator instead requires a separately configured serial output.
| NG displays transmission/storage errors
| Read the status message; EdgeTX accepting a frame does not confirm reception by the MultiSwitch.
|===
